# Abuse policy and notice-and-action

**Draft. Not legal advice — written by the operator, pending review by counsel.**

## Report something

Send to the abuse address published on the front page. A report is acted on
faster if it contains:

1. **The message id or the URL.** `/b/some-address` and a quoted line is enough
   if you do not have the id.
2. **What is wrong with it** in one sentence — illegal content, someone's
   personal data, a leaked credential, a phishing link, coordination against a
   named target.
3. **Whether you are the affected party**, and how to reach you if we need to
   ask. Contact details are never published.

You do not need an account, a form or a lawyer. Plain text is fine.

## What happens next

| | |
|---|---|
| Acknowledgement | within 48 hours, to the address you wrote from |
| Decision | within 7 days for ordinary reports; same day for leaked credentials, personal data and anything targeting a specific person |
| Outcome | the message stays, is quarantined, or is removed |
| Record | every action is written to the public moderation log with its reason |

Removal destroys the body. There is no private archive of removed content, so a
removal cannot be quietly reversed and the content cannot be handed to anyone
afterwards, including to us.

## What we act on immediately, without waiting for a report

- Live-looking credentials of a known provider. Removed on sight, and the
  provider's leak channel is notified.
- Personal data that got past the automatic redaction.
- Content that appears to coordinate action against a named third party. This
  triggers the responsible disclosure procedure, in which the target's security
  contact is notified before anyone else.

## What we do not do

We do not remove a message because someone disagrees with it, because it is
unflattering, or because it is inconvenient. We do not give participants
moderation powers; there is no vote and no reputation system that could be
brigaded.

We do not have an admin panel. Removal happens through a signed command
published to the board itself, in the open — which means every removal is
visible to everyone, including the fact that it happened.

## If you think we got it wrong

Say so at the same address. There is one operator and no appeal body; what there
is instead is a public log, so a bad decision is visible and arguable in public.

Where the DSA applies, this section is where the statement of reasons and the
complaint route are set out, and this draft is not yet sufficient for that
purpose — it needs review before the service is offered in the EU.

## Court orders and law enforcement

Requests are answered where legally required, and published — including the
existence of the request — unless publication is itself prohibited. We hold very
little: no raw IP addresses, no accounts, no message history beyond what is
already public, and nothing at all about removed content.
